## Open decisions

### DEC-013: Details data fetching

| Option                       | Considerations                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------ |
| `append_to_response`         | Fewer client-visible requests; larger combined payload and coupled failure behavior. |
| `Promise.all` parallel calls | Failure isolation and explicit learning; more requests.                              |
| Sequential calls             | Easy dependency reasoning; creates waterfalls.                                       |

Needed by: PH-3. Owner decision:

### DEC-014: Caching and revalidation

| Option                           | Considerations                                               |
| -------------------------------- | ------------------------------------------------------------ |
| Fetch-level caching/revalidation | Familiar and local; exact Next 16 behavior must be verified. |
| Next 16 Cache Components opt-in  | Newer model; teaches current framework but adds setup.       |

Needed by: PH-8. Owner decision:

### DEC-016: Actor popularity

| Option                         | Considerations                                            |
| ------------------------------ | --------------------------------------------------------- |
| Show raw TMDB popularity score | Faithful to source; users may read it as rank.            |
| Compute/display a local rank   | Clear ordering; rank scope and stability must be defined. |

Needed by: PH-4. Owner decision:

### DEC-018: Similar vs recommendations

| Option                   | Considerations                                           |
| ------------------------ | -------------------------------------------------------- |
| Similar endpoint         | Directly matches spec wording; may be less personalized. |
| Recommendations endpoint | Potentially richer relevance; changes semantics.         |

Needed by: PH-3. Owner decision:

### DEC-020: Callback hardening

| Option                                                             | Considerations                                               |
| ------------------------------------------------------------------ | ------------------------------------------------------------ |
| Short-lived httpOnly issued-token cookie and reject unknown tokens | Reduces replay/forgery risk; more state and expiry handling. |
| Trust valid TMDB callback token only                               | Simpler; weaker correlation protection.                      |

Needed by: PH-6/PH-8. Owner decision:

### DEC-021: Logout

| Option                               | Considerations                                                     |
| ------------------------------------ | ------------------------------------------------------------------ |
| Delete local cookie only             | Fast and reliable local sign-out; TMDB session remains active.     |
| Delete local cookie and TMDB session | Revokes remote session; endpoint/error lifecycle must be verified. |

Needed by: PH-6/PH-8. Owner decision:

### DEC-022: Logged-out mutation buttons

| Option                            | Considerations                                         |
| --------------------------------- | ------------------------------------------------------ |
| Disable with login affordance     | Clear state; visitor must seek login.                  |
| Allow click and redirect to login | Smooth intent preservation; more return-path handling. |

Needed by: PH-7. Owner decision:

### DEC-023: Genre list loading

| Option                       | Considerations                                                                                                                                                                                                                                                                                                            |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Server-read in shared layout | Consistent navbar; layout data can affect every route. TMDB has separate genre lists for movies and TV (⚠️ UNVERIFIED — check official docs), so the navbar Genres dropdown must be aware of the current media type. List pages also need the relevant genre list when validating `genre`; see `routes-and-url-state.md`. |
| Cached server module/read    | Avoids repeated calls; cache policy must be chosen.                                                                                                                                                                                                                                                                       |
| Client suggestions endpoint  | Dynamic; loading state in every navbar and extra browser request.                                                                                                                                                                                                                                                         |

Needed by: PH-1/PH-8. Owner decision:

### DEC-027: Navbar Genres dropdown semantics

| Option                | Considerations                                                                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A. Contextual         | Show movie genres by default and TV genres on `/tv` routes; compact and context-sensitive, but the same menu changes meaning by route.                 |
| B. Two labeled groups | Show separate Movies and TV groups, each linking to its own route; explicit and discoverable, but the menu is longer.                                  |
| C. Movies only        | Keep the navbar dropdown for movies and expose TV genres through in-page filter chips; simpler navbar, but TV filtering is less globally discoverable. |

Needed by: PH-1. Owner decision:

### DEC-026: Discover presets per category

| Option                 | Considerations                                                                                                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Top Rated              | Choose a minimum `vote_count` threshold so a tiny number of votes cannot dominate; exact threshold is owner-defined.                                         |
| Now Playing / Upcoming | Choose date window, release type, and region; exact values and supported parameters must be verified against official docs.                                  |
| TV equivalents         | Define date/status, vote-count, region, and any equivalent discover constraints for airing today, on the air, popular, and top rated; verify each parameter. |
| Minimal presets        | Use only verified parameters and accept broader results until product expectations are clearer.                                                              |

Needed by: PH-2. Owner decision:
